## 해소됨 (2026-06-10 마이그레이션 정밀 분석으로 확정)
- ✅ **[명단 수] 최종 53명.** 세 숫자의 정체가 규명됨:
  - **56명** = 옛 회원관리_사양서의 추정 검증치(Handover.xlsx 기준)
  - **63명** = 0003 1차 임포트(3시트 병합 시 차량만 있는 사람 등 포함)
  - **53명** = 0004·0007 정제판(중복·비회원·OB 제외) = **최종**
  - 근거: 모든 임포트가 `delete from members where chapter_id='새서울'` **후** `insert`(=append 아닌 **교체**). 최신 임포트 `0007_all_in_one.sql`이 53행. → 최종 상태 = 53.
  - ⚠️ 잔여 한계: anon 키는 RLS로 members를 못 읽어 **라이브 행수 재조회는 미실시**. 단 교체-패턴 + 실행기록상 53이 확정적. (라이브 대조용 SQL은 아래 "참고" 참조)
- ✅ **[status 제약] `활동/휴면/비활동/OB` 확정.** 0006에서 변경, 0007에서 재선언. **라이브 분포(2026-06-10): 활동 51 · 비활동 1 · 휴면 1** = 53. (0007 직후 활동52/휴면2에서 임원이 2건 손수정한 상태)
- ✅ **[grade 제약] 라이브 = 6종(유보회원 포함). 드리프트 해소.** 라이브 조회 결과 등급 분포에 **유보회원 1명 실재**(정31·부부9·명예8·준4·유보1·신입0). CHECK 제약은 위반행을 막으므로 = **라이브 제약이 유보회원을 허용**(판정 **(a) 수동 ALTER 적용됨**). 마이그레이션 파일(0002, 5종)이 뒤처졌던 것 → **`0021_grade_add_yubo.sql`로 소급 기록해 파일=DB 일치 완료.** 따라서 앱 UI의 유보회원 옵션은 정상 동작(버그 아님).

## 확인 필요 / 미결정
- **[회원 로그인 방식] 미결정 (택1).** 회원도 임원처럼 매직링크로 로그인하나, 기본 메일은 rate limit이 막음. ① **Gmail SMTP**(도메인 불필요·앱비번 1개·하루 500통 — Resend+도메인보다 간단) 또는 ② **회원은 로그인 없이**(공개/링크 공지 + 출석 QR, 임원만 로그인). 둘 다 미적용.
- **[환경변수] 외부 AI 키**(Cloudflare/Gemini/Recraft/Pixabay)가 운영 환경(Vercel)에 설정·작동하는지 = 확인 필요.
- **[레거시] `app/members/MembersTable.tsx`(@tanstack/react-table)** 미사용 — 회원 화면은 `MembersList.tsx`로 교체됨. 삭제 후보(기능 영향 없음 확인 필요).

## 향후 방향 / 미착수
- **모임온(MoimON) SaaS — 미착수, 단 전략 확정(2026-06-11).** 방향: **CBMC용·일반용을 따로 만들지 않고, 하나의 설정가능 멀티테넌트 제품**으로 만든다. **이 새서울 repo를 고치지 않고 새 이름·새 repo·새 DB로 분리**하며, 새서울은 그 제품의 **고객 1**이 된다(이 앱은 그대로 운영 유지). **착수 순서 = PRD 먼저**(별도 챗/프로젝트에서 작성 후 가져와 구현).
  - 그 제품이 멀티테넌트가 되려면 결국 필요한 4가지(이 repo가 아니라 새 제품에서 처음부터 설계):
    1. **`chapter_id`(=org) 동적화** — 로그인 사용자의 조직 주입, DB 함수 내부 `'새서울'` 고정 제거
    2. **조직별 admin 격리** — 전역 admin → 조직 단위 관리자
    3. **브랜딩·옵션 변수화** — 제목·환영문구·포스터·SMS·카테고리(회원등급/공지분류/회비)를 조직 설정값으로
    4. **온보딩** — 가입 시 조직 생성 + 범용 랜딩을 현관으로
  > ⚠️ 판매/구독/요금 모델은 아직 PRD 미작성. design-briefs도 "이 앱 자체는 판매용 아님·새서울 현관"이라 명시 → 이 repo에서 SaaS화하지 말 것.
- **참여도(활동도) 자동화:** 현재 status는 수기. 출석 데이터 기반 자동 산정(🟢활발/🟡보통/🟠저조/🔴장기미참)은 출석 누적 후 도입 예정.

## 참고 — 라이브 DB 대조용 SQL (임원이 SQL Editor에서 실행)
anon 키는 RLS로 막혀 코드가 직접 못 읽음. 아래는 결과가 숫자·enum뿐이라 안전(민감정보 없음).
```sql
-- 1) 실제 회원 수 (정본 주장: 53)
select count(*) as 회원수 from public.members where chapter_id = '새서울';

-- 2) grade/status CHECK 제약의 실제 허용값 (유보회원 포함 여부 판정)
select conname, pg_get_constraintdef(oid) as 제약정의
from pg_constraint
where conrelid = 'public.members'::regclass and conname like 'members_%_check';

-- 3) 등급/상태 실제 분포
select grade, count(*) from public.members where chapter_id='새서울' group by grade order by 2 desc;
select status, count(*) from public.members where chapter_id='새서울' group by status order by 2 desc;
```
