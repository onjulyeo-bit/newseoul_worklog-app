## ⚠️ 지금 적용해야 할 것 — 게스트 명단(2026-07-31, 코드는 배포됨/DB는 대기)

게스트(방문자) 명단 기능 코드는 완료됐지만, **마이그레이션은 수동 적용**이라 아래 2단계를 해야 실제로 켜진다.

1. **DB 마이그레이션 적용** — Supabase SQL Editor에 `supabase/migrations/0056_guests.sql` 전체를 붙여넣고 실행. (guests 테이블 + 익명 체크인 RPC 3종 생성)
   - 적용 전에는 체크인·식대 화면에서 게스트 목록 조회가 빈 값이 되고, 붙여넣기 저장 시 오류가 난다. 반드시 코드 배포 후가 아니라 **적용 먼저/동시**.
2. **21명 초기 명단 입력** — 마이그레이션 적용 후, **체크인·식대** 화면에서 이 게스트들이 올 **해당 회차(모임 탭)를 선택** → 게스트 카드의 **[＋ 명단 붙여넣기]** → 아래 블록을 그대로 붙여넣고 **[21명 추가]**. (번호·`이름(지회)` 자동 인식, '153'·'윤중y' 안전)

```
1.김병민(다니엘) 2.박예찬(다니엘) 3.황혜진(153) 4.최성근(무역센터) 5.안경희(무역센터) 6.최수열(남부연합) 7.이동희(남부연합) 8.윤상조(남부연합) 9.강희창(153) 10.이석용(153) 11.노현국(153) 12.이정숙(153) 13.서대반(윤중y) 14.안병은(윤중y) 15.김성준(윤중y) 16.정행창(윤중y) 17.윤영환(윤중y) 18.김인남(윤중y) 19.한동석(윤중y) 20.태준호(153) 21.송승환(153)
```

> 게스트는 **모임(회차)별**이라 다음 모임에는 그 모임 탭에서 새로 입력하면 된다. QR 체크인 화면에는 회원 명단 아래 '게스트' 섹션으로 뜨고, 게스트도 본인 이름을 눌러 출석한다.

## 향후 방향 / 미착수
- **카카오 사용자 ↔ 회원(members) 매칭**: 카카오로 들어온 사용자(이메일 없을 수 있음)를 기존 `members` 레코드와 연결하는 로직 없음. 식별·연결 방식 설계 필요.
- **역할 자동 승격**: 신규 로그인은 `guest` 고정. `guest → member` 승격 정책/화면 필요.
- **다지회 지원**: 지금은 `'새서울'` 하드코딩 + RLS가 chapter_id를 안 봄. 다지회로 가려면 (1) 앱 쿼리의 chapter_id 동적화, (2) RLS에 chapter_id 격리 추가가 동시에 필요.
- **공통 인증 게이트**: 페이지마다 흩어진 `getUser()` 검사를 미들웨어/레이아웃 레벨로 정리 검토.
