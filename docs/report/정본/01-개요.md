## 1. 정체와 목적
**새서울 CBMC 아름다운 만남** — 기독실업인회 새서울지회의 금요 조찬 정기모임 운영 앱.
임원(회장·총무·간사)이 회원 명단부터 모임 일정·출석·식대·회계·공지·포스터까지 한 곳에서 처리한다. 사용자층에 고령 임원이 포함되어 **가독성·단순함이 제1원칙**.

## 2. 도메인 규칙 (코드에서 확인된 핵심 비즈니스 규칙)
- **회원 분류 3층 분리** (한 칸에 섞지 않는다):
  - **등록여부(registration):** `등록회원` / `비등록`
  - **등급(grade):** `명예회원` `정회원` `부부회원` `준회원` `신입회원` `유보회원` — 1인 1개, 회비 결정. (라이브 제약 6종 확정; 유보회원은 0002 이후 수동 추가→`0021`로 소급 기록)
  - **상태(status):** `활동` `휴면` `비활동` `OB` — 1인 1개, 참여/활동도 (0006/0007에서 옛 활동중/유보/등록전/OB에서 변경됨)
  - **이력태그(tags[]):** `증경회장` 등 복수. 평생 예우 직책은 태그(배지)로 표시
  - ※ "올해 임원(지회장·총무·간사 등)"은 태그가 아니라 별도 `officer_terms`(연도별)로 관리 — 평생예우 ≠ 1년 역할
- **회비:** 기존회원 600,000원 / 신입회원 650,000원 (`chapters.dues_*`). 유보·OB 면제. 부부회원 합산 1건.
- **식대 ≠ 회비:** 식대는 모임 밥값(`meetings.fee`/`attendance.paid`), 회비는 연간 회원회비(`transactions`). 완전 별개.
- **민감정보 저장 금지:** 주민번호·계좌번호 저장 안 함. (회원 테이블·거래 테이블 주석에 명시)
- **자동화 한계(정책):** 카톡 자동발송·통장 입금 자동확인 불가 → **문구 생성·복사**, 사람이 입금 체크.
- **권한:** `admin`(임원)만 회원 개인정보(members) 접근. `chapters`·`officer_terms`·`events`는 로그인 시 열람·임원만 수정. RLS는 `is_admin()`(security definer로 재귀 회피) 기반.
- **체크인:** 모임별 토큰으로 비로그인(anon) 자가 출석. 실수 시 체크아웃 가능.

## 3. 구현된 전 기능 (라우트 25개 기준)
- **인증:** `/login`·`/`(Welcome) 매직링크, `/auth/confirm`(token_hash 검증)·`/auth/callback`·`/auth/signout`. 세션 갱신은 `proxy.ts`(※ Next16에서 middleware→proxy 개명) + `lib/supabase/middleware.ts`.
- **홈/대시보드:** `/`(역할분기: 익명=Welcome / 회원=공지홈 / 임원=회원목록), `/dashboard`(임원 통계).
- **회원관리:** `/`(임원시 = `MembersList.tsx`), `/members/[id]`(상세·편집 전체폼), `/members/new`(추가), `/members/import`(엑셀). 현 화면은 **커스텀 클라이언트 컴포넌트**(통계 4칸·등급/상태/등록 필터·검색·열선택·데스크톱 표/모바일 카드) + 행 클릭 시 **오른쪽 상세 드로어**(보기/편집, **사진 업로드**·**태그 칩 편집**). ⚠️ 옛 `MembersTable.tsx`(@tanstack/react-table)는 **미사용 레거시**(임포트 안 됨, 정리 대상 → 03).
- **일정:** `/schedule`(`ScheduleBoard` — 자동생성·엑셀·이벤트·인라인편집·저장).
- **출석·식대:** `/attendance`(회차탭·QR·식대설정·납부체크·**미납자 SMS 버튼**·미납 독촉문구), `/attendance/stats`(`StatsView`), `/checkin/[id]`(QR 비로그인).
- **회계:** `/finance`→`/finance/transactions`(서브탭 공통, `FinanceTabs`), `/finance/import`(카뱅 자동분류), `/finance/report`(결산·인쇄).
- **공지:** `/notices`(`NoticesBoard`·회원홈 히어로 겸용). **콘텐츠:** `/content`(`ContentHub`→포스터 에디터·경조사). **아카이브:** `/archive`. **역할관리:** `/roles`(`RolesBoard` — 임원이 admin/member/guest 지정).
- **API:** `/api/occasion-extract`(Gemini), `/api/poster-bg`(Flux/Recraft), `/api/stock`.
- **모임온 랜딩:** `/preview-landing`(→ `Landing.tsx`, 프리뷰 전용).

## 7. 새서울(운영) vs 모임온(판매) 분리 현황 (진단 기준선, 2026-06-10)
**한 줄 결론: 운영의 99%가 새서울 전용(A). 모임온(B)은 코드 분기 없음. 둘이 공유하는 기반(C)은 스키마·유틸뿐.**

- **단일 지회 고정(A):** `chapter_id='새서울'`이 **쿼리 필터 23곳 + insert/DB함수 7곳 ≈ 30곳**에 하드코딩. 로그인 사용자의 지회를 동적으로 읽는 로직 **없음**.
- **멀티테넌트 = 미행사(C):** `chapters` 테이블·`chapter_id` FK·RLS로 여러 지회를 **담을 수는 있으나** seed는 새서울 1행뿐, 한 번도 행사된 적 없음.
- **전역 admin(A):** `profiles.role=admin`은 전역 1종. "**지회별 관리자**" 개념 없음 → 테넌트 격리 불가.
- **브랜딩 고정(A):** 제목·메타·환영문구·포스터·SMS에 "새서울 CBMC" 하드코딩(~55곳). 2026-06 개편으로 **헤더 = "CBMC 새서울지회"**·첫화면 = `Welcome`(새서울)로 오히려 더 새서울에 박힘.
- **모임온 자산(B, 불활성):** `Landing.tsx`(범용 판매 랜딩) + `.moimon` 스코프 CSS는 존재하나 **`/preview-landing`에만 격리**, 실서비스 동선(`/`=Welcome 새서울)엔 없음.
- **공유 기반(C):** `lib/supabase/*`, `parseMembersXlsx`·`classifyTxn`·`generateSchedule`·`exportTable` 등 순수 유틸 + 멀티테넌트-가능 스키마.

> ⚠️ **"디자인은 모임온, 제품은 새서울"** — 2026-06 전 화면을 *모임온 디자인 시스템*으로 입혔지만, **브랜딩·데이터·인증은 전부 새서울 고정(A)**이라 제품은 여전히 단일 지회다. 디자인 톤 통일 ≠ 멀티테넌트화.
> 📌 **전략 결정(2026-06-11):** 판매용 모임온은 *CBMC용·일반용 따로*가 아니라 **하나의 설정가능 멀티테넌트 제품**으로, **새서울과 완전 분리(새 이름·새 repo·새 DB)** 한다. **새서울 = 고객 1**. 착수 전 **PRD 먼저**. → 03 향후방향.

> ✅ **기획 범위 초과 구현:** 옛 사양서는 "회원관리만"이었으나, 실제론 회비·주간(일정)·출석·회계·공지·아카이브 **전 모듈이 구현**됨. QR체크인·AI포스터(Flux/Recraft)·경조사 AI추출(Gemini)·카뱅 회계 임포트는 사양서에 없던 기능. → **코드가 사양서를 크게 앞섰다.** 사양서는 참고용 과거 문서.
