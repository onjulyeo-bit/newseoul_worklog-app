# 지회 운영 허브 + 서류함 — 설계 (2026-09-10)

> 서명 모듈(e-Sign)을 독립 탭에서 빼고, "운영매뉴얼" 탭을 **지회 운영** 허브로 확장해 그 안에 **매뉴얼**과 **서류함**(전자서명 + 보관 서류)을 둔다. 보관 서류는 서명 완료본 자동 보관 + 운영진 직접 업로드.

## 0. 결정 사항 (사용자, 2026-09-10)
- 서명자 화면은 **A안 유지**: 서명자는 빈 원본 + 본인 서명란만 본다. 다른 서명자의 서명은 관리자 현황판에서만.
- 아카이브(`/archive`)는 회원 전체 공개 영역이므로 운영 서류를 넣지 않는다.
- 탭 이름은 **"지회 운영"**.
- 보관 서류는 **자동 보관(서명 완료본) + 직접 업로드** 둘 다.

## 1. 메뉴 (`app/SiteNav.tsx`)
| 전 | 후 |
|---|---|
| main: … 체크인·식대 · **서명** · 회계 … | main: … 체크인·식대 · 회계 … (서명 탭 제거) |
| settings: **운영매뉴얼**(`/manual`) · 권한설정 | settings: **지회 운영**(`/ops`) · 권한설정 |

- 활성 탭 판정: `/ops`, `/ops/*`, `/manual/*`, `/sign/*` 모두 "지회 운영" 탭을 켠다. (`activeHref` 에 별칭 매핑 추가)
- `/manual`, `/manual/[key]`, `/sign/*` 라우트는 유지. `/manual` 허브 페이지는 `/ops` 로 redirect.
- 노출 대상은 기존과 동일(운영진 admin + 읽기 운영진 viewer).

## 2. 허브 `/ops`
- 서버 페이지 `app/ops/page.tsx` → `getStaffGate()` 로 isStaff 게이트 → 데이터 로더 → `OpsHub` 순수 컴포넌트.
- 카드 스타일은 `app/manual/manualCss.ts` 의 `mn-card` 계열을 `app/ops/opsCss.ts` 로 옮겨 `.moim-ops` 스코프로 재사용.
- 섹션 2묶음:
  1. **매뉴얼** — `MANUAL_SECTIONS` 4개 카드 → `/manual/[key]` (수정일 메타 유지)
  2. **서류함** — 카드 2개
     - **전자서명** → `/sign` · 메타 "진행중 n건"
     - **보관 서류** → `/ops/docs` · 메타 "n건" (서명 완료본 + 업로드 합산)
- 데이터: `manual_sections(key, updated_at)`, `sign_requests(status)` 카운트, `chapter_docs` 카운트. 테이블이 아직 없거나 오류면 0으로 처리(마이그레이션 적용 전 배포 안전).

## 3. 보관 서류 `/ops/docs`
- 서버 페이지 → `DocsView` (클라이언트).
- **목록 = 두 소스의 합집합**, 최신순:
  - `sign` 소스: `sign_requests` 중 `status='completed'` → 제목·`doc_category`·`updated_at`. 열기/다운로드는 기존 `GET /api/sign/pdf/[id]`. 삭제·수정은 여기서 하지 않음(서명 현황판에서).
  - `upload` 소스: `chapter_docs` 행. 열기/다운로드 `GET /api/docs/[id]`. canEdit 이면 수정(제목·분류·메모)·삭제.
- 상단 **분류 칩**(전체 + 5분류) 필터. 각 행: 배지(서명본/업로드) · 제목 · 분류 · 날짜 · 메모 · 파일형식/크기 · [열기] [다운로드].
- canEdit 이면 **[＋ 업로드]** 버튼 → 인라인 폼(제목, 분류, 메모, 파일). 파일 제한: `.pdf .hwp .hwpx .docx .xlsx .pptx .png .jpg .jpeg`, **5MB**. 클라이언트에서 base64 변환 후 서버 액션 `uploadDoc`. 
- 분류 상수 `lib/docCategories.ts`: `임원·연임 서류` / `규약·정관` / `회의록·총회` / `공문·대외` / `기타`. 코드 고정.

## 4. 서명 마법사 연동
- `/sign/new` 1단계(제목·설명·마감)에 **분류** 셀렉트 추가, 기본값 `임원·연임 서류`. `createSignRequest` 가 `doc_category` 저장.
- `/sign` 목록의 "완료 서류함" 탭은 유지하되 탭 라벨을 "완료" 로 바꾸고, 빈 상태 문구에 "보관 서류(`/ops/docs`)에서도 볼 수 있어요" 링크.

## 5. DB — `supabase/migrations/0060_ops_docs.sql` (SQL Editor 수동 적용)
```sql
create table public.chapter_docs (
  id uuid primary key default gen_random_uuid(),
  chapter_id text not null default '새서울',
  title text not null,
  category text not null,
  note text,
  file_name text not null,
  file_mime text not null,
  file_size int not null,
  file_data text not null,          -- base64 (≤5MB 원본)
  uploaded_by uuid references auth.users(id),
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
-- RLS: 읽기 is_staff(), 쓰기 is_admin()
alter table public.sign_requests add column doc_category text not null default '임원·연임 서류';
-- 서명 4개 테이블: select 정책을 is_staff() 로 (viewer 읽기), insert/update/delete 는 is_admin() 유지
```
- 마이그레이션 적용 전 배포되어도 허브는 0건으로 표시되고, `/ops/docs` 는 안내 문구("마이그레이션 0060 적용 필요")를 띄운다.

## 6. API
- `GET /api/docs/[id]` — 관리자 세션(RLS is_staff) 으로 `chapter_docs` 조회 → base64 디코드 → `Content-Type: file_mime`, `Content-Disposition: inline; filename*=UTF-8''…`. `?download=1` 이면 `attachment`.
- service_role 사용 안 함(원칙).

## 7. 문서 갱신
- 정본 01 라우트 표: `/ops`, `/ops/docs`, `/api/docs/[id]` 추가, `/manual` 설명 갱신, `/sign` 진입점 표기.
- 정본 02 변경이력 1줄, 03 서명 모듈 표 아래 "지회 운영 허브" 상태 + 0060 적용 안내.
- 핸드오프 문서 §3 파일 지도에 허브 경로 추가.

## 8. 검증
1. `npm run build`.
2. 프리뷰 셸(`app/preview-shell/page.tsx`, 목 데이터)로 허브·보관 서류 목록·업로드 폼 스크린샷 → 삭제.
3. 배포 후 사용자 로그인: 탭 "지회 운영" → 허브 → 전자서명(기존 목록) → 보관 서류 업로드 1건 → 열기·다운로드 → 삭제.
